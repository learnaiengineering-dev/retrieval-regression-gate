Retrieval Regression Gate

A better average score can hide a query whose best evidence moved down. This gate compares your retriever before and after, query by query, and fails the build when any query got worse.

Try it

The sample below is a new retriever that improves the mean score but pushes one query's best result down. Open "Edit the data" to change rankings or grades, or paste your own.

Grades: 3 is the best evidence, 0 is judged not relevant, and a document with no grade is unjudged and scores zero. Everything runs in your browser. Nothing is sent anywhere.

Ways to use it

Command line

Run it locally or in any CI. Exit code 1 means a query regressed.

GitHub Action

One step in a workflow. Writes the result to the job summary.

Python library

Call compare() from your own eval code and get a JSON-ready report.

Embeddable widget

Show the gate result on your own site, docs or dashboard.

Claude skill

Let a coding agent run the gate and explain the regression.

Install and run

pip install retrieval-regression-gate
retrieval-gate baseline.json candidate.json judgments.json --k 10 --tolerance 0.02
# exit 0 pass, 1 a query regressed, 2 bad input

In GitHub Actions

- uses: actions/checkout@v4
- uses: learnaiengineering-dev/retrieval-regression-gate@v0.1.0
  with:
    baseline: eval/baseline.json
    candidate: eval/candidate.json
    judgments: eval/judgments.json
    k: "10"
    tolerance: "0.02"

From Python

from retrieval_gate import compare

result = compare(baseline, candidate, judgments, k=10, tolerance=0.02)
if not result.passed:
    for message in result.failures:
        print(message)
    raise SystemExit(1)

Embed the widget

The widget is one JavaScript file with no dependencies. Copy retrieval-gate-widget.js next to your page (host it yourself; there is no CDN to depend on), then add the element:

<script type="module" src="/assets/retrieval-gate-widget.js"></script>

<retrieval-gate heading="Retrieval check" k="10" tolerance="0.02">
  <script type="application/json">
    { "baseline": {}, "candidate": {}, "judgments": {} }
  </script>
</retrieval-gate>

Or show a ready-made page in an iframe using embed.html:

<iframe src="/assets/embed.html" title="Retrieval gate" width="100%" height="380" loading="lazy"></iframe>

Attributes

AttributeDefaultWhat it does
k10Cutoff: only the top k results are scored.
metricndcgndcg, precision, recall or rr.
tolerance0Allowed per-query drop before a query counts as regressed.
min-meannoneAlso fail when the candidate mean is below this floor.
editableoffAdds an "Edit the data" panel so visitors can try their own rankings.
themeautolight or dark. Auto follows the visitor's system setting.
headingnoneOptional title shown above the result.

Use it from JavaScript

const gate = document.querySelector("retrieval-gate");
gate.data = { baseline, candidate, judgments };          // set or replace the data
gate.addEventListener("gate-result", (e) => {
  console.log(e.detail.passed, e.detail.failures);        // same shape as the Python report
});

// Or use the logic without the element:
import { compare } from "/assets/retrieval-gate-widget.js";
const report = compare(baseline, candidate, judgments, { k: 10, tolerance: 0.02 });

The gate-result event bubbles and carries the report, or null when the input is invalid. The widget's numbers are checked against the Python package with a shared test file, so both give the same results.

Security and content policy

  • No network access. The widget never fetches or sends anything. It only reads the data you give it.
  • No inline scripts or style attributes. Styles are applied with a constructed stylesheet, so a strict script-src 'self' policy works. A browser without constructed stylesheets falls back to a <style> element, which a strict style-src policy would block, leaving the widget unstyled.
  • Your text is never run as HTML. Query names and document ids are inserted as text.
  • Pin the file. If you load it from a shared location, add a subresource integrity hash:
openssl dgst -sha384 -binary retrieval-gate-widget.js | openssl base64 -A
# then: <script type="module" src="..." integrity="sha384-<hash>" crossorigin="anonymous"></script>

For your organisation

QuestionAnswer
Does it send data anywhere?No. The CLI and the widget make no network calls and have no telemetry. Rankings and judgments stay on your machine.
What does it depend on?Nothing at runtime: the Python package has no dependencies and the widget is one file.
Can it run offline or behind a firewall?Yes. Mirror the package on your internal index, or vendor the single widget file.
Are results repeatable?Yes. The same inputs always give the same numbers, so reports are safe to diff and archive.
Is the output stable?The JSON report has a schema_version and the exit codes are documented. Pin an exact version in your pipeline.
How is it released?Published to PyPI from GitHub with trusted publishing, so there is no long-lived upload token to leak.
What is the licence?MIT. You can use, modify and redistribute it commercially. Keep the licence, the file header and the NOTICE.
Who reviews the labels?You do. The gate is only as good as your judgments, so keep them in version control and review changes like code.

Limits

  • Scores describe your labels. They do not prove an answer is correct.
  • Unjudged documents count as zero, so a good result nobody labelled looks like a miss. The report counts them so you can see when labels are missing.
  • Rankings are compared by document id. The tool never reads document contents.
  • The widget shows the gate result. It does not run your retriever.
